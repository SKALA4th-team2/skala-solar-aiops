# 여러 발전소의 발전량과 ASOS

2026-10-07에 기존 하동하수처리장 자료와 별도로 추가했다. GitHub `origin/main`의 `ffff81f` 코드에서 `Date,Close,Volume`과 `(20, 2)` 입력을 확인했다. 기존 하동 CSV와 서빙 코드는 변경하지 않았다.

## 사용할 파일

[발전소별 파일 목록](INDEX.md)에서 발전소·호기를 고른 뒤 `uploads/`의 CSV 하나를 사용한다. `catalog.csv`의 `primary_upload`는 그 호기의 가장 긴 연속 구간이다. 원본의 호기 번호를 그대로 나눈 것이므로 **43개 호기는 43개 독립 사업장을 뜻하지 않는다.**

| 구분 | 이번 생성 결과 |
| --- | --- |
| 추가 발전실적 원본 | 39개 공개 파일 (기존 하동하수처리장 제외) |
| 사양·좌표 참고 원본 | 2개 공개 파일 |
| 일별 정규화 | 36개 실적 파일, 45개 호기, 138,075행 |
| 업로드 가능한 구간 | 34개 실적 파일, 43개 호기, 78개 CSV, 113,944행 |
| 실제 `build_sequences`로 확인한 입력/정답 | 112,384개, 입력 모양 `(20, 2)` |
| 지역 | 부산·인천·하동·삼척·영월·이천·음성·제주 |

**학습·성능평가는 실행하지 않았다.** `upload_ready`는 형식과 날짜·수치 검증을 통과했다는 뜻이다. 고장 라벨이나 높은 예측 성능을 보증하지 않는다.

### 업로드 열

| 열 | 의미 |
| --- | --- |
| `Date` | 발전실적 날짜 d, `YYYY-MM-DD`, 한국 날짜 |
| `Close` | d일의 발전량, kWh. 원본 일 총량을 그대로 사용 |
| `Volume` | **달력상 d-1일**의 ASOS 일사량, MJ/m². 예보나 d일 관측값이 아님 |

UTF-8, BOM 없음. `Stop`은 추가하지 않았다. 확인되지 않은 정지일을 정상/고장으로 임의 라벨링하지 않기 위해서다. 업로드 API와 `load_rows()`에는 이 세 열이면 충분하다. `zero_generation`은 분석용 일별 파일에 별도로 있다.

기존 `hadong_upload.csv`와 동일한 시차다. 예를 들어 입력 마지막 행이 12월 30일이면 그 행의 `Volume`은 12월 29일 관측값이고, 다음 날 발전량이 정답이다. 기상청 일자료는 전일 자료를 당일 10시 이후 확인할 수 있다는 [공식 안내](https://data.kma.go.kr/data/grnd/selectAsosList.do?pgmNo=36)에 맞춰 사용한다. 과거 확정 관측값으로 만든 파일이며 최초 발표본의 수정 이력까지 재현하지는 않는다.

**발전소나 떨어진 구간들을 단순 이어 붙이지 않는다.** 현재 `build_sequences()`는 행 순서만 읽으므로 경계를 넘겨 잘못된 20일 창을 만들 수 있다. 같은 발전소의 여러 구간을 사용할 때도 구간별로 창을 만든 후 합쳐야 한다. 시간 기준 평가에서는 평가 기간을 먼저 정하고, 그 이후 구간을 학습에 넣지 않는다.

현재 앱은 최신 업로드 파일 하나, 스케일러 경로 하나, 모델 이름 하나를 사용한다. 데이터 교체 시 해당 발전소의 스케일러와 모델을 새로 만들고, 여러 모델을 보관하려면 발전소별 경로·이름을 분리해야 한다. `/predict`의 기존 `close > 0`, 정수 `volume` 제한은 그대로이므로 0 발전량·소수 일사량 요청의 HTTP 예측 호환성까지 해결한 작업은 아니다. 업로드와 학습 입력 검증까지만 완료했다.

## ASOS 원본 대조

사용자가 제공한 `ASOS_2013.csv`~`ASOS_2025.csv`에서 필요한 관측소 18개와 7개 열만 추렸다. 전체 원본 13개 파일의 SHA-256·크기·행 수를 [weather_verification.json](weather_verification.json)에 남겼다. 원본 폴더는 읽기만 했고 전체 연도별 파일을 중복 복사하지 않았다.

기존 `hadong_daily_full.csv`의 2013-01-01~2025-12-31, 4,748일과 대조한 결과:

- 광양 일사량 원관측값과 결측 보정값: 불일치 0, 최대 차이 0.
- 광양 일조시간 원관측값과 품질검사·보정값: 불일치 0, 최대 차이 0.
- 광양 최고기온과 일사량 보정 출처: 불일치 0.
- 기존 `hadong_upload.csv`의 4,746행 `Close`, `Volume`: 불일치 0, 최대 차이 0.

날씨 비교가 실패하면 `prepare_weather.py`는 추출본을 새로 저장하지 않고 중단한다. `build.py`도 대조 결과와 추출본 해시를 검사한다.

### 지역별 날씨 연결

발전소 주소·지역을 기준으로 선택한 **지역 관측 대리값**이다. 현장 일사량이 아니며, 최단거리나 예측 성능을 최적화한 연결은 아니다. 관측소 변경이 일사량 수준을 바꿀 수 있으므로 모델 평가와 드리프트 해석에서 실제 사용 관측소를 함께 확인한다.

일부 기본 관측소는 일사량이 장기간 없어 대체 관측소가 주로 사용된다. 제주 반대편이나 산지를 사이에 둔 지역은 특히 대표성 검토가 필요하다. `daily/`의 `gsr_station_id`, `gsr_is_fallback`, `gsr_lag1_station_id`로 실제 연결을 추적한다. 일조시간·최고기온은 기본 관측소 값으로 별도 보관하고 업로드 입력에는 넣지 않는다. 날씨는 2025년까지 있으므로 2026년 발전량은 분석용 일별 파일에 보존하되 업로드에는 들어가지 않는다.

## 품질 검사와 제외

원본은 바이트 그대로 `raw/`에 보관했다. 호기별로 날짜를 정렬하고, 일 총량과 24시간 합계, 숫자·결측·음수, 중복 날짜를 검사했다. 동일 중복은 하나로 정리하고 서로 다른 중복은 정상 학습 구간에서 제외한다. 호기가 없는 행은 임의로 다른 호기에 합치지 않았다.

일 합계 검사의 허용오차는 절대 0.05kWh + 상대 1e-6이다. 공식 용량을 확실히 연결한 경우 시간 최대값이 용량의 1.2배를 넘거나 일 총량이 용량×24를 넘으면 검토 대상으로 표시한다. **이 기준은 보수적인 자료 선별 기준이며 고장 판정 기준이 아니다.** 현재 공식 사양과 과거 실적의 설비 변경 차이일 수도 있다. 용량 연결이 불명확하면 값을 추측해 채우지 않는다.

발전량 또는 날씨가 유효하지 않은 날짜에서 구간을 나누며, 중간 날짜를 삭제한 뒤 앞뒤를 붙이거나 보간하지 않는다. 365일 이상 연속되고 발전량 0인 날의 비중이 25% 이하인 구간만 업로드용으로 쓴다. 이 조건은 이번 데이터 선별 기준으로, 모델의 배포 게이트나 드리프트 임계값과 무관하다. 나머지 구간과 0 발전량은 원본·분석 파일에 남는다.

| 보류/제외 대상 | 처리 |
| --- | --- |
| 삼척사택·안동소내 | 월별 자료이므로 일별 자료로 늘리지 않음. 원본만 보관 |
| 부산철도 2호기 | KPX 계량 별도 형식, 단위 미확인. 원본만 보관 |
| 행원소수력 태양광 | 용량 대조·0 발전량 비중과 연속 구간 기준을 통과한 업로드 구간이 없어 분석용만 보관 |
| 익산 다송리 | 일 합계 불일치·용량 대조에서 의심 구간이 많아 분석용만 보관. 두 발전소명 표기는 같은 다송리로 묶되 원본 표기 보존 |
| 신인천 해수취수구 | 호기 공란 365행 제외. 확인 가능한 호기 구간만 사용 |
| 익산 다송리 공란 호기 | 110행을 다른 호기에 임의 결합하지 않음 |

세부 기간·수치·제외 구간은 [catalog.json](catalog.json)에 있다. 원본 열의 단위가 `kw`이거나 생략된 32열 형식은 기존 하동 조사와 같은 근거로 kWh로 해석했다. 명시된 `kWh`와 추정한 경우를 `unit_basis`로 구분한다.

## 파일과 출처

| 경로 | 내용·출처 |
| --- | --- |
| `raw/{source_id}.csv` | 공공데이터포털의 한국남부발전 원문 CSV. 대부분 CP949 |
| `raw/{source_id}.json`, `sources.json` | 각 CSV의 공식 상세 URL·실제 다운로드 URL·수정일·수집시각·SHA-256·이용 조건 표기 |
| `weather/asos_selected_daily.csv` | 사용자 제공 기상청 연도별 ASOS 일자료에서 관측소·열을 선택한 값. `stnId`, `stnNm`, `tm`, `sumGsr`(MJ/m²), `sumSsHr`(시간), `ssDur`(가조시간), `maxTa`(℃) |
| `daily/{source_id}_u{unit}.csv` | 호기별 발전량과 같은 날 날씨, 전날 일사량, 품질 플래그. 업로드용이 아님 |
| `uploads/*.csv` | 검사에 통과한 연속 구간의 `Date,Close,Volume` |
| `catalog.csv`, `catalog.json`, `INDEX.md` | 발전소·호기·지역·용량·기간·상태·파일 경로와 검사 결과 |
| `weather_verification.json` | 사용자 ASOS 원본과 기존 하동 자료 대조 결과 |
| `validation.json` | 원본 전 행 대조, 달력 연속성, 날씨 시차 및 실제 학습 입력 코드 실행 결과 |

분석용 주요 열: `gen_kwh`는 원본 일 총량, `hourly_sum_kwh`는 24개 시간값 합, `peak_interval_kwh`는 시간값 최댓값, `capacity_kw`는 확인된 사양 용량이다. `numeric_valid`, `sum_matches`, `duplicate_conflict`, `capacity_suspect`, `generation_valid`, `zero_generation`은 검사 플래그다. `gsr_mj_m2`는 같은 날 관측값, `gsr_lag1_mj_m2`는 하루 전 관측값이다. 원본 날짜가 없는 날은 분석용 파일에도 생성하지 않는다.

남부발전 자료 41건은 수집 당시 공식 페이지의 **이용허락범위 제한 없음** 표기를 확인했다. ASOS 출처는 [기상청 지상(종관, ASOS) 일자료 조회서비스](https://www.data.go.kr/data/15059093/openapi.do)이며, 2026-10-07 공식 페이지에서 무료·공공누리 제1유형(출처표시)을 확인했다. 원본 API 응답을 이 저장소에서 새로 받은 것은 아니다. 사용자 제공 파일의 출처 계보와 해시를 보존하며 출처 표기를 유지한다. 이용 조건은 해당 공식 서비스와 [기상청 저작권 정책](https://www.kma.go.kr/kmadev/guide/copyright.jsp)을 따른다.

출처 표시 예: `발전량: 한국남부발전·공공데이터포털(각 source_id 링크), 기상자료: 기상청 ASOS 일자료. 관측소 선별·일사량 시차 결합: 본 프로젝트.`

생성·재검증 명령은 [도구 설명](../../tools/build_multi_plant/README.md)에 있다.
