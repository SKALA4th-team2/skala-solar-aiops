# 데이터

대시보드에 올릴 업로드용 CSV 와 그 바탕이 되는 자료를 둔다. `project/data/` 는 서빙 앱의 코드 폴더이므로 데이터 원본은 여기에 따로 둔다.

**아직 파일이 없다.** 통합 보고서가 어느 파일을 쓸지 정리하면 넣는다.

## 원본

| 자료 | 출처 | 기간 |
| --- | --- | --- |
| 한국남부발전(주)\_하동하수처리장 태양광발전실적 | [공공데이터포털 15043409](https://www.data.go.kr/data/15043409/fileData.do) | 2013-01-01 ~ 2026-02-28, 하루 한 줄 |

이용 조건과 출처 표기 방법은 파일을 넣을 때 확인해 적는다([`../docs/followups.md`](../docs/followups.md) 5번).

## 업로드 파일의 형식

서빙 앱의 업로드는 `Date`, `Close`, `Volume` 열이 있어야 하고 최소 41행이어야 한다. HAIC 에서는 `Close` 가 종가, `Volume` 이 거래량이었다. 태양광에서 각 열에 무엇을 넣을지는 [`../docs/proposal/domain-mapping.md`](../docs/proposal/domain-mapping.md)와 결정 기록을 따른다.

## 파일을 넣을 때 적을 것

파일마다 아래를 표로 적는다.

| 파일 | 행 수와 기간 | 각 열의 뜻과 단위 | 만든 스크립트 | 쓸 때 주의할 점 |
| --- | --- | --- | --- | --- |
| | | | | |

- 예측 시점에 받을 수 없는 값이 들어간 파일은 파일 이름과 이 표에 그 사실을 적는다. 그런 파일로 얻은 수치는 "상한"이다.
- 비어 있는 날을 어떻게 채웠는지, 정지일을 어떻게 표시했는지를 적는다.

## 규칙

- 여기 있는 파일은 손으로 고치지 않는다. 만드는 스크립트를 [`../tools/`](../tools/)에 두고 다시 만든다.
- 서빙 앱이 실제로 읽는 것은 대시보드로 올린 사본(`project/data/uploads/`)이다. 그 폴더는 커밋하지 않는다.
