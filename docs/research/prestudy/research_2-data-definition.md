# 조사 2-data-definition (2. 데이터 정의) — 출처 검증을 마친 결과

## 1. (1-가) 각 컬럼의 정확한 뜻

- 상태: 확인함 / 검증 판정: 일부만 뒷받침함
- 답: 포털의 컬럼 정의에는 뜻이 적혀 있지 않다. 컬럼 표의 '항목 설명' 칸은 앞 8개 열은 항목명을 그대로 반복하고 1~24열은 모두 '시간대별 발전량'이며, '단위' 칸은 32개 열 전부 '-'다(2026-10-06 페이지를 다시 열어 확인). 아래는 원본 CSV 4,807행으로 다시 계산해 맞춘 관계다(scratchpad 사본 data_15043409.csv 사용. 포털 미리보기 50행과 값이 같음을 확인).
- 년월일: YYYY-MM-DD, 하루 1행. 2013-01-01~2026-02-28, 빠진 날과 중복 없음
- 호기: 발전기 번호. 전부 1
- 총량(kw): 1~24열의 합. 4,807행 모두 일치
- 평균(kw): 총량÷24. 자릿수 규칙이 세 구간이다(조사 결과의 '2020-08-01부터 소수 3자리'를 고침). 2013-01-01~2020-07-31(2,769행)은 정수로 반올림(131.196→5), 2020-08-01~2021-07-31(365행)은 반올림하지 않은 몫 그대로(소수 최대 5자리, 190.674→7.94475), 2021-08-01부터(1,673행) 소수 3자리로 반올림(226.236→9.427, 80.244→3.344)
- 최대(kw): 24개 시간값 중 최댓값. 전 행 일치
- 최소(kw): 24개 시간값 중 최솟값. 전 행 일치. 4,798일이 0이고 2015-04-25~05-03의 9일만 0.006
- 최대(시간별_kw): 최대(kw)와 같은 값. 단 2017-03-01~2020-07-31 중 1,006일은 소수 둘째 자리 아래를 버린 값(52.788→52.78)
- 최소(시간별_kw): 0을 뺀 시간값 중 최솟값(24시간이 모두 0인 24일은 0). 구간별 규칙은 다섯 개다(조사 결과의 '2017-03~2023-03에 섞여 있다'를 구체화). 2013-01-01~2017-02-28 정확히 일치, 2017-03-01~2020-07-31 소수 둘째 자리 아래 버림(0.864→0.86), 2020-08-01~2022-06-30 정확히 일치, 2022-07-01~2023-03-31 소수 첫째 자리로 반올림(0.162→0.2, 0.006→0), 2023-04-01부터 정확히 일치
- 1~24: 시간대별 발전량. 값이 0.006의 배수다. 예외는 2016-02-24~26의 14개 값뿐이다(45.2, 39.4처럼 소수 1자리)
정리하면 요약 6열 중 평균·최대(시간별)·최소(시간별)는 기간에 따라 자릿수 규칙이 달라진다. 규칙이 바뀌는 날은 2017-03-01, 2020-08-01, 2021-08-01, 2022-07-01, 2023-04-01이다. 믿고 쓸 수 있는 것은 총량과 1~24열이다.
추정: 2022-07-01과 2023-04-01은 과거 판의 자료 끝 날짜(_20220630, _20230331) 바로 다음 날이다. 해마다 덧붙인 묶음마다 내보내기 자릿수 설정이 달랐던 것으로 보인다.
- 프로젝트에 주는 영향: 모델 입력과 정답은 총량과 1~24열에서 직접 계산하고, 평균·최대(시간별)·최소(시간별) 열은 다섯 번 규칙이 바뀌므로 입력으로 쓰지 않는다. 결측·정지 구간을 '합계 0'으로만 거르면 2015-04-23~05-05가 남으므로 기준(예: 합계 1 미만)을 따로 정해야 한다.
- 이미 확인된 사실과 어긋나는 점: '발전량 0인 날 24일(2016-12-22~26, 2018-07-13~31)'은 합계가 정확히 0인 날로는 맞다. 다만 합계가 0보다 크고 1 미만인 날이 15일 더 있다: 2015-04-23~05-03(11일)과 05-05(1일), 2018-07-04·07-07·07-12(3일). 2015-04-23~05-05는 사이의 05-04(3.48)를 포함해 13일 연속 사실상 정지 구간인데 '0인 날' 조건으로는 걸러지지 않는다. 이 중 2015-04-25~05-03의 9일은 24시간 모두에 0.006~0.018이 찍혀 있다. 그 밖의 이미 확인된 사실(4,807일, 빠진 날 없음, 호기 1, 합계 일치, 중앙값 220.11, 최대 379.752, 시간 최댓값 52.788)은 다시 계산한 값과 일치한다.
- 검증자 메모: 직접 확인한 것: 포털 페이지를 다시 열어 컬럼 표 32행의 항목 설명과 단위 칸, 설명문, 전체 행 4807을 대조했다. 오픈API 명세는 페이지에 들어 있는 명세 JSON에서 응답 항목 이름과 설명을 뽑아 대조했다. CSV는 Decimal 연산으로 전 행을 다시 계산했다(스크립트: (작업 폴더)/solar/verify2r/c1.py, c2.py, c3.py). 합계·최대·최소 일치, 0.006 배수와 예외 14개, 최대(시간별) 1,006일, 예시 값(131.196→5, 80.244→3.344는 2026-02-26, 52.788→52.78은 2017-03-07, 0.162→0.2는 2022-07-06)은 모두 재현됐다. 고친 것: (1) 평균 열은 2020-08-01~2021-07-31에 반올림 없이 소수 5자리까지 나오고, 3자리 반올림은 2021-08-01부터다. (2) 최소(시간별) 열은 2020-08-01~2022-06-30에 정확히 일치하는 구간이 끼어 있고, 2022-07-01~2023-03-31의 274행은 전부 소수 첫째 자리 반올림으로 설명된다. (3) impact의 규칙 변경 시점에 2021-08-01과 2022-07-01을 더했다. 과거 판 (이하 생략, 전문은 JSON)

## 2. (1-나) 'kw'로 표기된 값이 실제로 kWh인지

- 상태: 추정 / 검증 판정: 출처가 뒷받침함
- 답: 하동 데이터셋 페이지에는 단위 정의가 없다(컬럼 표의 단위 칸이 전부 '-', 확인함). 실제 단위는 kWh로 보는 것이 맞다(추정, 근거 다섯 가지).
1) 같은 기관·같은 관리부서(AI업무혁신부)가 2026-09에 올린 같은 유형의 데이터셋(세화리, 신인천본관주차장, 와산리)은 같은 자리의 열 이름이 '총량(kWh)', '최대(시간별_kWh)', '0-1시 발전량(kWh)'이고 '설비용량(kW)' 열이 따로 있다. 익산 다송리도 '총량(kWh)'과 '0-1시 발전량(kWh)'을 쓴다(최대·최소 열은 없음).
2) 같은 부서가 올린 '태양광발전분야 용어 정보'(2025-12-18)가 발전량은 일정 기간 생산한 총 전력량으로 kWh 단위, 출력은 순간 전력으로 W 또는 kW 단위라고 구분해 정의한다. 하동 페이지 설명문은 이 값을 '일간 총 발전량', '시간별 발전량'이라고 부른다(검증 중 추가한 근거).
3) 총량이 24개 시간값의 합이다. 순간 출력(kW)이라면 합이 뜻을 갖지 않는다.
4) 시간값이 0.006 단위로 끊어진다. 적산 전력량계 눈금으로 보인다.
5) 남부발전 사양정보의 설치용량 55kW와 맞는다. 시간 최댓값 52.788(용량의 96%, 2017-03-07 13열), 일 최대 379.752(2019-03-31, 등가 6.9시간), 전체 평균 201.2/일로 이용률 15.2%.
따라서 시간값은 그 1시간의 발전량(kWh, 그 시간 평균 출력 kW와 숫자가 같음), 총량은 kWh/일이다.
주의: 사양정보 안에서 하동하수처리장은 '55kW, 모듈 250W x 160, 인버터 55kW x 1EA'(모듈 합 40kW), 하동군보건소는 '40kW, 모듈 250W x 220, 인버터 40kW x 1EA'(모듈 합 55kW)로 적혀 있어 두 행의 모듈 수가 뒤바뀐 것으로 보인다(추정). 용량 자체는 실측과 맞는다. 하동보건소 미리보기 50일(2013-01-01~02-19)의 시간 최댓값은 34.528로 40kW 아래이고, 같은 50일 합계는 하수처리장이 보건소의 1.50배다(용량 비 55/40=1.375).
- 프로젝트에 주는 영향: 화면과 API 명세의 단위는 kWh로 적고, 원본 열 이름이 kw라는 점과 kWh가 추정이라는 점을 데이터 정의 칸에 한 줄 남긴다. 오차율 분모인 설비 용량은 55kW를 쓸 수 있다. 일 합계 기준 분모 1,320kWh(55kW x 24h)는 예측제도에 있는 정의가 아니라 이 프로젝트가 정하는 변형이므로 기획서에 그렇게 밝혀야 한다.
- 이미 확인된 사실과 어긋나는 점: 이미 확인된 사실의 열 이름 표기 '(kw)'와 실제 단위(kWh, 추정)가 다르다. 값 자체(중앙값 220, 최대 380, 시간 최댓값 52.8)와는 어긋나지 않는다. 사양정보 내부에서 하동하수처리장과 하동군보건소의 모듈 수 합계가 각자의 설치용량과 맞지 않는다(위 주의 참조).
- 검증자 메모: 직접 확인한 것: 세화리·와산리·신인천본관주차장·익산 다송리 페이지의 컬럼 표와 미리보기 머리글, 등록일·수정일을 대조했다(세화리 미리보기는 설비용량 999.6kW에 시간 최댓값 824.4로 kWh 해석과 맞음). 사양정보 미리보기에서 하동하수처리장과 하동군보건소 행을 글자 단위로 대조했고 모듈 합(250W x 160 = 40kW, 250W x 220 = 55kW)을 계산했다. CSV로 시간 최댓값 52.788(2017-03-07 13열), 일 최대 379.752, 평균 201.22, 이용률 15.24%를 다시 계산했다. 보강한 것: 같은 부서의 용어 정보 데이터셋(발전량은 kWh, 출력은 kW)과 하동보건소 미리보기 대조를 근거로 더했다. 고친 것: 익산 다송리에는 최대(시간별_kWh) 열이 없으므로 근거 1에서 따로 적었고, 일 최대를 379.8에서 원값 379.752로 적었다. 하동 파일 자체의 단위를 밝힌 공식 문서는 찾지 못했으므로 상태는 추정으로 둔다. 55kW를 뒷받침하는 남부발전 보도자료 등은 검색했으나 찾지 못했다.

## 3. (2) 시간대 열 1~24가 각각 어느 시간 구간인지(1이 0~1시인지, 한국 표준시인지)

- 상태: 추정 / 검증 판정: 출처가 뒷받침함
- 답: 열 N은 한국 표준시 (N-1)시~N시 구간의 발전량이다. 1은 0~1시, 24는 23~24시다(추정, 근거 세 가지). 하동 페이지는 1시부터 24시까지의 시간별 발전량이라고만 적고 구간과 시간대를 밝히지 않는다.
1) 같은 기관의 같은 유형 데이터셋(세화리, 와산리, 신인천본관주차장, 익산 다송리의 2026-09 등록본)은 같은 자리의 24개 열을 '0-1시 발전량(kWh)' ~ '23-24시 발전량(kWh)'으로 적는다. 오픈API 설명도 00시부터 24시까지 1시간 단위라고 한다(응답 항목 이름은 '발전량 1시'~'발전량 24시').
2) 발전량이 있는 4,783일에서 발전량 가중 중심 시각을 구하면, 열 N을 (N-1)~N시로 읽을 때 태양 남중 시각(위치 35.05885N 127.7799E, KST 평균 12:29에 균시차 가감)과 평균 +0.04시간 차이다. N~(N+1)시로 읽으면 +1.04시간, UTC라면 9시간 어긋난다.
