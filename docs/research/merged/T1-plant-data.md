## 발전소와 데이터의 정의

설비 용량은 공식 사양·설비현황 원문에서 다시 확인한 55kW로 통일한다. 출처 없는 50kW 가정을 채택할 근거는 없지만, 시간값이 50을 넘는다는 사실만으로 설비 정격을 확정할 수는 없다. 시간대 열 h는 (h-1)시~h시의 발전량(kWh)으로 해석하되 공식 정의가 없는 추정임을 유지한다. MAE를 고정 용량으로 나눠도 모델 순위는 그대로다. 게이트는 일 합계 RMSE와 같은 입력의 기준 모델로 정하고, 시장 정산 기준 4%·6%를 일 합계 오차에 적용하지 않는다.

이 절에서 쓰는 말은 다음과 같다.

- "사전 조사"는 웹 조사와 Open-Meteo 날씨로 한 분석 묶음이고, "ASOS 분석"은 기상청 종관기상관측(ASOS) 일자료와 발전 실적을 결합해 실습 LSTM(직전 20일 값으로 다음 날 값을 맞히는 순환 신경망)을 직접 돌린 분석 묶음이다. 두 묶음은 서로의 결과를 모르고 진행됐다.
- "원자료"는 공공데이터포털의 「한국남부발전(주)_하동하수처리장 태양광발전실적_20260228」 CSV 다. 하루가 한 행이고, 요약 열 6개와 시간대 열 1~24 가 있다. "호기"는 발전기 번호다.
- "이용률"은 발전량을 (설비 용량 x 시간)으로 나눈 값이다. "MAE"는 예측과 실제의 차이를 절댓값으로 평균한 값, "RMSE"는 차이를 제곱해 평균한 뒤 제곱근을 취한 값이다. 단위는 둘 다 하루 발전량 kWh 다.
- "예측제도"는 전력거래소의 재생에너지 발전량 예측제도다. 오차율을 시간대별로 |예측 - 실제| ÷ 설비 용량으로 계산하고, 이용률이 10% 이상인 시간대만 평균한다.
- "대리 모형"은 실습 LSTM 대신 가볍게 돌린 회귀 모형(Ridge, 입력은 직전 20일의 일 합계)이다. 대리 모형의 수치는 우리 모델의 성능이 아니다.
- 근거 칸의 `T1/` 은 `files/T1-plant-data/` 를, `solar/` 와 `asos/` 는 같은 scratchpad 아래의 사전 조사 폴더와 ASOS 분석 폴더를 뜻한다.


**이번 검증의 근거.** `tools/verify/verify_t1t2.py`가 저장소 원본을 직접 계산했고 `verify_official_neighbors.py`가 새로 받은 공식 CSV를 대조했다. 산술 재현과 설비 원인 확정은 다르다. `solar/`·`asos/` 경로는 원 작성자의 외부 작업 폴더이며 현재 저장소에 없을 수 있다. 아래 표의 원 조사 `확인함`은 이번 독립 재확인 여부를 뜻하지 않으며, 범위는 마지막 ledger를 따른다.

### 팀이 정할 것

**1. 설비 용량을 어느 값으로 통일할 것인가**

- 선택지: 55kW 로 통일한다. 50kW 를 그대로 둔다.
- 추천: 55kW 로 통일한다.
- 근거: 문서 네 건이 0.055MW 로 일치한다. 원자료의 시간값은 50 을 45번 넘었고 최대가 52.788 이라 50kW 로는 용량의 105.6% 가 된다. 이웃 4곳은 시간 최대가 공식 용량의 81.2~96.9% 이고 용량을 넘은 곳이 없다.
- 발표까지: 할 수 있다. ASOS 분석의 "용량 대비 MAE" 수치는 다시 학습하지 않고 50/55 를 곱하면 된다(예: 5.51% 는 5.01%). 원 ASOS 보고서는 수정하지 않고 병합 문서에 55kW 채택과 환산값을 기록한다. 50kW 가정에서 나온 후보 입력 "5kW 이상 낸 시간 수"는 발전량만 넣은 모델과 차이가 없던 후보라(RMSE 80.61 / 79.82kWh 대 80.42 / 79.84kWh, 선형 회귀 / 그래디언트 부스팅) 다시 돌릴 필요가 없다.

**2. 용량을 분모로 쓰는 오차율을 기획서와 게이트에 쓸 것인가**

- 선택지: 쓰지 않고 kWh 기준 RMSE 와 합계 대비 절대오차율(절대오차의 합 ÷ 실제값의 합)을 쓴다. 일 단위 오차율(MAE ÷ (55kW x 24시간))을 설명 지표로 쓴다. 예측제도식 오차율을 쓴다.
- 추천: 기본 게이트는 RMSE와 같은 입력의 기준 모델로 두며, 시장 정산의 4%·6%를 일 단위 지표에 적용하지 않는다. 발표에서 예측제도를 언급할 때만 "시간대별 예측이 있어야 계산할 수 있고, 일 단위 예측을 평균 시간 비중으로 나누면 55kW 기준 11~14% 수준(대리 모형과 단순 예측)"이라고 참고로 적는다.
- 근거: 평가 구간이 조금씩 다르기는 하지만, 55kW 기준 일 단위 오차율은 고정값 예측 5.01%, 20일 평균 5.01%, 대리 모형 4.53%, ASOS 분석의 LSTM 4.73% 로 0.5%p 안에 몰려 있어 같은 평가일·용량에서 MAE와 모델 순위가 같으므로 판별력이 사라진다는 근거는 되지 않는다. 같은 예측을 시간 분포로 나눈 참고 실험은 대상 시간 전체 평균 11.45%, 일별 동일가중 평균 12.33%다. 두 제출값과 정산 규칙을 재현한 실제 정산 오차가 아니다. 합계 대비 절대오차율은 용량과 무관하다(같은 구간의 고정값 예측 34.8%).

- 선택지: 확인된 것만 적는다. 추정(모듈 220장, 제작사, 정남향)까지 적는다.
- 추천: "한국남부발전의 55kW 태양광, 2011년 준공, 경남 하동군 하동읍 신기리 하동공공하수처리시설 안, 250W급 모듈과 55kW 인버터 1대, 설치각 30도"로 적는다. 원 조사에 있는 2012년 3월 전력시장 수급 개시는 이번에 재확인하지 못했으므로 소개의 확정 사실에서 뺀다.
- 근거: 모듈 수는 공식 표 안에서 용량과 맞지 않고(160장 x 250W = 40kW), 방위각은 어느 자료에도 없다. 지번은 세 자료가 서로 다르다.
- 발표까지: 할 수 있다.

### 확인하지 못한 것

- 55kW 가 모듈 용량인지 인버터 용량인지, 준공 뒤 모듈이나 인버터를 교체하거나 증설했는지는 확인하지 못했다. 전력거래소 표의 용량은 "준공 당시 기준"이라고 주석이 달려 있다.
- 모듈 수(공식 표 160장, 추정 220장), 제작사, 인버터 제조사와 모델, 패널 방위각, 고정식 여부, 지붕·지상 구분을 확인하지 못했다.
- 준공 일자와 정확한 지번을 확인하지 못했다.
- 시간대 열의 구간과 단위(kWh)를 밝힌 하동 파일의 공식 문서가 없다. 0.006 눈금이 계량기의 어떤 설정에서 나오는지도 모른다. 남부발전 AI업무혁신부에 물어야 한다.
- 오픈API 로 2026-03 이후 이 발전소 자료가 나오는지와 발전소 코드를 확인하지 못했다. 가입이 필요함.
- 2016-12-28 이 복사라는 것과 2016-02-24~26 이 수기 입력이라는 것은 값의 형태에서 나온 추정이다. 남부발전에 확인하지 않았다.
- 정지 사유(2015-04~05, 2016-12, 2018-07)와 2020-09-08 에 발전량이 6.67kWh 였던 이유를 확인하지 못했다.
- 남부발전 홈페이지의 두 쪽이 하동군 태양광 합계를 0.565MW 와 0.558MW 로 다르게 적는다. 0.558 은 네 곳의 합과 같고, 0.565 가 왜 7kW 큰지는 모른다.
- 부지 사용 조건, 관리 사업소, 출처 표기 양식을 확인하지 못했다.
- 원대조 때는 문서 사본을 사용했다. 설비 용량, 준공 시기, 좌표, 갱신 주기, 이용 허락 표기, 세화리 열 이름, 오픈API 표기는 작업 폴더에 받아 둔 사본에서 해당 줄을 직접 읽었다. 이번에는 설비 사양·설비현황·좌표 CSV를 새로 받아 하동 행을 대조했고, 광양 관측소 좌표는 기상청 위키에서 확인했다. 전력거래소 두 판, 준공 월·2012년 수급개시, 공공데이터법 조문, 과거 판 행 수·파일 40개는 다시 확인하지 못했다.
- 우리 LSTM의 실제 시장 정산 오차율은 계산하지 못했다. 시간대별 예측이 없다. ASOS 분석 LSTM 의 55kW 기준 수치는 다시 학습하지 않고 환산한 값이다.
- 이번에 이웃 4곳 CSV를 다시 내려받아 행 수, 기간, 합계 일치, 0 인 날과 시간 최대를 재계산했다. 사실상 정지 구간과 복사·수기 입력 여부는 점검하지 않았다.
- 일출·일몰 시각은 직접 계산한 값이고 한국천문연구원 공식 시각과 대조하지 않았다.
