## 발전소와 데이터의 정의

문서: [`T1-plant-data.md`](T1-plant-data.md)

설비 용량은 55kW 로 통일한다. 한국남부발전과 전력거래소의 문서 네 건이 55kW 로 일치하고 원자료의 시간값이 50 을 넘은 시간이 45개(최대 52.788)이므로, ASOS 분석이 쓴 50kW 는 출처 없는 가정이었고 원자료와도 맞지 않는다. 시간대 열 h 는 한국 표준시 (h-1)시~h시에 쌓인 발전량(kWh, 추정)이고, 용량을 분모로 쓰는 오차율은 용량에 반비례해 바뀔 뿐 배운 모델과 배우지 않은 모델을 가르지 못하므로 게이트에 쓰지 않는다는 데 두 조사의 결론이 같다.

| 정할 것 | 추천 |
| --- | --- |
| 설비 용량을 어느 값으로 통일할 것인가 | 55kW 로 통일한다. |

## 설비 이력, 정지일, 출력 수준이 바뀐 시점

문서: [`T2-history-outage.md`](T2-history-outage.md)

출력 수준은 네 번 바뀌었는데, 2015-01-02~03 에 약 9% 내려갔다가 2015-05-16 에 돌아왔고, 2018-08-01 재가동 뒤 2023년까지는 여름마다 6~9포인트 낮아졌으며, 2021년 5월 중순(05-13~05-22 사이)에 약 9% 내려간 뒤 돌아오지 않다가 2024-03-22(추정)의 인버터 교체를 거쳐 2024년 5월부터 약 6% 올랐다. 정지일은 일곱 목록이 일합계(하루 발전량 합계, kWh)가 정확히 0 인 24일에서만 일치하고 47일이 서로 달랐는데, 날짜 단위로 대조한 결과 학습에서 뺄 정지일은 50일(전면 정지 40일, 부분 정지 10일)이고 2024-03 이후에만 나타난 절반 출력일 15일은 따로 표시한다. 서빙 시점 판정은 "일합계가 1 kWh 미만이거나 5 kWh 미만이 이틀 연속이면 정지, 광양 날씨로 계산한 기대 발전량이 80 kWh 이상인데 실제가 그 60% 미만이면 출력 저하"라는 규칙 하나로 두고, 원인은 2024년 3월의 인버터 교체(대상과 계약은 문서로 확인, 시공일은 추정)만 말할 수 있다.

## 날씨 자료와 두 번째 입력

문서: [`T3-weather-input.md`](T3-weather-input.md)

두 번째 입력(실습 LSTM, 곧 수업에서 받은 실습 코드의 예측 모델이 발전량과 함께 받는 둘째 값이고 원래 코드의 Volume 자리)은 대상일(맞히려는 날, T)에 대한 24시간 전 일사량 예보로 정하고, 운영 모델의 업로드 파일은 `hadong_upload_forecast_jma.csv` 를 쓴다. 이 예보를 넣은 실습 LSTM 의 RMSE(예측과 실제의 차이를 제곱해 평균한 뒤 제곱근을 취한 값, 단위는 하루 kWh)는 42 ~ 46kWh 로 발전량만 넣은 77 ~ 79kWh 보다 낮고, 지난 관측은 넣어도 효과가 없으며(79.2 대 78.5kWh), 대상일의 실제 관측을 넣은 23kWh 는 예측 시점에 받을 수 없는 값이라 '예보가 완벽하다면'을 보이는 시연과 사후 감시에만 쓴다. 기상청 광양 관측소의 일사량과 Open-Meteo(키 없이 쓰는 공개 날씨 API)의 재분석 일사량(관측과 수치 모델을 합쳐 다시 계산한 격자 값)은 같은 날 상관 0.947, 차이의 RMSE 2.37MJ/m2(관측 평균의 15.7%)로 맞고, 위성 영상에서 계산한 일사량은 관측과 상관 0.981 로 더 가깝다.

| 정할 것 | 추천 |
| --- | --- |
| 두 번째 입력을 무엇으로 할까 | 대상일에 대한 24시간 전 일사량 예보를 쓴다. |
| 업로드 파일로 무엇을 쓸까 | 운영 모델은 hadong_upload_forecast_jma.csv 를 쓴다. hadong_upload.csv 는 예보 없음 비교선과 2021년 구간 시연에 쓴다. hadong_upload_forecast_proxy.csv 는 상한 한 줄을 보일 때만 쓰고 예보가 완벽하다고 가정했다고 적는다. |
| 언제 예측하고 예보를 어떻게 받을까 | 전날 20시 이후에 예측한다. Forecast API 를 모델 지정 없이 불러 내일 값을 받고, 받은 값과 시각을 기록한다. |
| 사후 감시(성능 지표)에는 어느 날씨를 쓸까 | 발표에서는 광양 ASOS 관측으로 이미 계산된 지표(hadong_daily_full.csv, 2013 ~ 2025년)를 쓴다. 운영 설계에는 위성 일사량을 키 없이 받는 경로로 함께 적는다. 예보는 쓰지 않는다. 판정 방법은 드리프트 주제가 정한다. |

## 예측 성능과 배포 게이트

문서: [`T4-performance-gate.md`](T4-performance-gate.md)

두 조사와 보완 조사가 남긴 예측 파일을 같은 898일(2023-07-17 ~ 2025-12-30)과 같은 지표로 다시 계산하면, 하루 발전량 예측 오차(RMSE)는 발전량만 넣을 때 77 ~ 78kWh, 지난 관측 날씨를 더해도 78 ~ 79kWh, 실제 24시간 전 일사량 예보를 넣을 때 45 ~ 46kWh, 예보가 완벽하다고 가정할 때 23kWh 이고, 두 조사의 수치 차이는 평가 구간과 날씨 자료의 출처로 모두 설명된다. ASOS 분석이 모의로 추정한 예보 성능 43 ~ 52kWh 는 실측과 맞았지만, 그 개선은 학습이 없는 규칙(최근 7일 효율 x 예보, 47kWh)도 내는 수준이어서 "모델이 배웠다"가 아니라 "예보를 넣었다"의 효과로 말해야 한다. 배포 게이트는 입력 구조마다 따로 두어 상한 시연은 절댓값 32kWh, 실제 예보 구조는 "7일 평균 RMSE 의 80% 이하이면서 같은 예보로 계산한 규칙 RMSE 의 105% 이하", 발전량만 구조는 "7일 평균과 20일 평균 가운데 낮은 쪽의 RMSE 미만"으로 하고, 제도의 6%·4% 는 어느 오차율 정의로도 게이트에 그대로 쓸 수 없다.

| --- | --- |
| 발표에 쓸 성능 수치의 기준 구간 | 공통 898일 값을 본문 표로 쓰고, 시연 화면에 찍히는 값은 업로드 파일 시험 구간의 값이라고 한 줄로 밝힌다. 수치는 네 줄로 말한다. 발전량만 77 ~ 78kWh, 실제 예보 45 ~ 46kWh(48시간 전 예보면 52 ~ 54kWh), 학습 없는 규칙 47kWh, 상한 23kWh |
| 실제 예보를 넣는 구조의 배포 게이트 | 둘째 선택지. 구현이 어려우면 상수 47.5kWh 로 시연하고 기획서에는 둘째 선택지를 적는다. 48시간 전 예보를 쓰게 되면 그 예보로 만든 규칙과 견준다 |

| 합계 치우침을 게이트의 보조 조건으로 둘지 | 둘째와 셋째를 함께 둔다 |

## 드리프트 판정, 시연 구간, 재학습

문서: [`T5-drift-demo.md`](T5-drift-demo.md)

드리프트 판정은 실습 코드의 최근 21건 RMSE 가 아니라 성능 지표(실제 발전량을 그날 관측 날씨로 계산한 기대 발전량으로 나눈 값)의 하락으로 하고, 21건 RMSE 는 입력 이상을 잡는 보조 경보로만 남긴다. 2021년 5월의 실제 하락은 일사량 예보 자료(2022-07-03 이후)와 겹치지 않으므로 감시 지표만 과거 자료에 돌려 보이고, 예측 모델과 재학습까지 도는 시연은 예보가 있는 2025년 구간의 발전량을 14% 낮춰 넣는 방식으로 나눈다. 재학습의 효과는 일사량 예보를 넣은 모델에 수준 변화를 넣었을 때 치우침이 되돌아온다는 데까지만 말할 수 있고, 2021년의 실제 하락이나 발전량만 넣은 모델에서는 RMSE 로도 치우침으로도 말할 수 없다.

| 정할 것 | 추천 |
| --- | --- |

| 정지와 성능 저하를 어떻게 가를 것인가 | 첫째와 둘째를 함께 쓴다. 정지나 보류이면 재학습을 걸지 않고 알림만 남기며, 보류가 길어지면 따로 알린다 |

## 제도의 현재 상태와 시나리오의 규칙상 근거

문서: [`T6-scheme.md`](T6-scheme.md)

재생에너지 발전량 예측제도(태양광·풍력 사업자가 다음 날의 시간대별 발전량을 전력거래소에 미리 내고, 맞힌 정도에 따라 kWh당 정산금을 받는 제도)는 2026-10-07 조회 기준으로 육지에서 시행 중이고, 종료일은 정해지지 않았으며 재생에너지 입찰제도가 도입되는 지역에서 그 시행과 동시에 종료한다는 조건만 규칙에 있다. 하동하수처리장 태양광(55kW)을 한국남부발전이 묶은 20MW 초과 묶음(예측형 집합전력자원)의 구성원으로 두는 시나리오는 규칙상 조건부로 가능하지만, 실제 편입 여부와 남부발전의 육지 묶음 자체가 확인되지 않았으므로 기획서에는 가정이라고 적어야 한다. 제도의 수치(4%, 6%, 10%)는 묶음 단위로, 시간대별로, 설비용량을 분모로 계산하는 값이어서 하루 합계를 예측하는 이 프로젝트의 배포 게이트나 드리프트 임계값으로 옮겨 쓸 수 없고, 배경 설명과 운영 목표의 참고선으로만 쓴다.

## 고객, 손익, Pain Point 의 근거

문서: [`T7-value.md`](T7-value.md)

고객은 작은 발전소를 20MW 넘게 묶어 전날 예측을 내고 정산금을 받는 전력 중개 사업자로 잡고, 돈의 근거는 발전소 한 곳(연 10만 원대)이 아니라 평균 규모 사업자(약 171MW, 정산금 총액 연 약 4억 원 추정)에 두며, 오차율 1%p 의 의미는 "정산 단가 약 9% 감소, 가정에 따라 7~17%"로 쓴다. 사전 조사 6 의 "집합 기준으로는 1%p 에 약 5%"와 "묶으면 오차가 상쇄된다"는 원자료로 다시 계산한 결과와 맞지 않으므로 쓰지 않는다. 하동하수처리장 한 곳의 8.5~9% 저하는 집합 정산금을 바꾸지 못하고(하동 5곳 집합 오차율 +0.06%p) 과거 값만 쓰는 LSTM 은 약 3주면 낮아진 수준을 스스로 따라가므로, Pain Point 와 운영 목표는 "재학습으로 정확도를 되찾는다"가 아니라 "발전소별 설비 이상을 2~4주 안에 알린다"로 잡아야 두 조사와 모두 맞는다.
