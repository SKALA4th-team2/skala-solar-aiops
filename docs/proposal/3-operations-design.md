# ③ 운영 설계

- 평가 항목: 2-1 (설계)
- 담당:
- 상태: 작성 전

## 통합가이드가 요구하는 것

배포 게이트 기준(입력 스키마 검증, 성능 회귀 테스트, 임계값), 모니터링 지표와 임계값, 드리프트 발생 시 대응 정책(알림 → 재학습 → 게이트 재검증 → 실패 시 기존 버전 유지 또는 롤백)을 근거와 함께 설계한다.

## 쓸 것

배포 게이트

- [ ] 입력 스키마 검증: 무엇을 거르는가 (길이, 값의 범위)
- [ ] 성능 기준: 지표, 기준값, 어느 구간으로 재는가
- [ ] 기준을 통과하지 못한 버전은 어떻게 되는가

모니터링

- [ ] 무엇을 지켜보는가 (지표)
- [ ] 얼마나 모아서 판단하는가 (창 길이)와 그 이유
- [ ] 임계값과 그 값을 고른 이유. 더 낮추거나 높이면 오경보와 놓침이 어떻게 달라지는가

드리프트 대응 정책

- [ ] 알림: 누구에게 무엇으로 알리는가
- [ ] 재학습: 어떤 데이터로, 처음부터인지 이어서인지
- [ ] 게이트 재검증: 재학습한 모델을 무엇으로 다시 확인하는가
- [ ] 실패했을 때: 기존 버전을 유지하는가, 되돌리는가
- [ ] 설비가 멈춘 날과 성능이 서서히 떨어진 날을 어떻게 가르는가
