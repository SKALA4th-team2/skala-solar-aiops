# 0013: 프론트를 제외한 다개소 백엔드·AIOps 구현

- 상태: 로컬 프로토타입 구현. 실제 운영 품질 승인과 구분한다.
- 날짜: 2026-10-07
- 근거: 사용자의 백엔드 전체 연결 요청. 0005~0008, 0011~0012의 제안을 아래 기본값으로 적용했다.

## 적용한 계약

LSTM 20일×2입력은 유지한다. 학습 자료의 숫자 ID는 `15043384_u1` → `15043384-u1`로 대응하고 하동은 `hadong-sewage`다. `plant_id` 생략 요청은 하동으로 처리한다. 용량 × 24시간으로 개소별 발전량 상한을 검사한다. 용량을 모르는 곳은 서빙·업로드를 보류한다.

기존 43개 모델을 다시 평가한 결과 33개를 준비된 운영 후보로 등록·활성화했다. 6개는 최초 게이트에 미달하고 4개는 용량을 확인하지 못했다. 통과하지 않은 기존 모델 파일을 지우거나 성능 수치에서 제외하지 않는다. 최초 게이트는 같은 시험 날짜에서 Mean7 RMSE의 80%, RuleC RMSE의 105% 이하, 편향 ±10%, 최소 180일이다. ±5% 초과는 경고다.

레지스트리는 `solar-daily-<plant_id>`, 실제 버전 번호를 응답한다. 모델·스케일러·입력 계약·자료 해시·학습 종료일을 manifest로 묶는다. `SOLAR_STATE_DIR`(기본 `project/data/runtime`) 아래 `models/<plant_id>/versions/<version>/`에 불변 묶음을 두고 `current.json`을 원자적으로 교체한다. 이는 0011의 단일 스케일러 경로 제안을 버전별 경로로 구체화한 것이다. `tools/multi_plant/bundle_check.py`도 이 묶음을 검사한다.

## 감시와 재학습

- 사후 관측 기반 expected로 PI를 계산한다. 예보 입력과 섞지 않는다. 초기 expected는 개소별 ASOS 관측과 2022~2023 발전량으로 만든 선형식이고 기준선은 2024년의 마지막 365일이다. 관측소는 지역 대리값이다.
- 최근 21일, 유효일 15일 이상, 하락 −7.5%, 앞 20일도 같은 하락이면 후보를 만든다. 실제/기대 비율은 PI 계산에서 0.5~1.5로 자른다. 30/80kWh 조건은 설비 용량/55kW에 비례한다.
- 정지·보류가 41일 안에 있으면 재학습을 막는다. RMSE가 최초 시험 RMSE의 1.5배를 넘는 것만으로는 재학습하지 않는다.
- 같은 끝 날짜의 같은 자료는 같은 판정·작업을 반환한다. 다른 자료를 같은 날짜로 보내면 409로 거절한다. 오래된 배치는 상태를 되돌리지 않는다.
- 별도 SQLite `jobs.db`에 작업과 감시 상태를 보존한다. 작업 키는 발전소·종류·끝 날짜다. 일꾼 하나와 OS 파일 잠금으로 동시 학습을 막는다. 중단 작업은 재시작 때 최대 2회 시도까지 복구하며 이력을 남긴다.
- API는 대기 작업을 기록하고 반환한다. 일꾼은 2초 간격으로 작업을 확인하고, 30초마다 개소별 새 업로드를 감시한다. 별도 기상 API 수집기는 기존 데이터 도구의 역할이다.
- 41일에서 앞 16개 정답으로 현재 가중치를 10 epoch, Adam 1e-4로 추가 학습한다. 스케일러는 재적합하지 않는다. 뒤 5개 정답은 학습에 쓰지 않는다.
- 재학습 게이트는 최초에 기록한 kWh 한도 이하이고 **같은 5일에서 기존 모델보다 나쁘지 않아야 한다.** 후자는 0005 제안에 추가한 보호 조건이다. 5건 게이트는 기능 시연용이며 운영 품질 보증이 아니다.
- 성공하면 이전 Production을 Archived로 내리고 champion과 현재 버전을 바꾼다. 새 파일을 먼저 검증·로딩하며 실패하면 기존 메모리 모델을 유지한다. 재시작 시 레지스트리와 포인터 불일치를 복구한다. 명시적 롤백 API가 있다.
- 같은 끝 날짜에 알려진 설비 용량의 절반을 넘는 곳이 함께 이상 신호를 보이면 공통 기상/자료 이상 후보로 작업을 보류한다. 원인 확정 진단은 아니다.
- 41일 작업만으로 365일 기준선을 재계산하지 않는다. 기준선은 보존하고, 정비 후 재설정은 365일 자료와 유효일 180일 이상을 확인하는 별도 API로 한다.

## 합계와 실행 단위

포트폴리오 예측은 같은 대상일의 구성원 예측을 더한다. 누락이 있으면 total을 null로 두고 partial을 따로 준다. 최초 평가는 공통 시험 날짜의 예측 합과 실제 합으로 계산했다. 구성 또는 모델 버전이 바뀌면 기존 품질 통과 표시를 재사용하지 않는다. 포트폴리오 감시는 같은 끝 날짜의 21일을 합산하며 정산용 지표가 아니다.

로컬은 API 8077과 학습 일꾼, 컨테이너 설정은 8099의 단일 컨테이너 안에 두 프로세스다. 로컬/컨테이너 상태·업로드·로그를 공유하지 않는다. Dockerfile의 주가 샘플 재학습을 제거하고 검증된 모델 seed를 새 저장소에 등록한다. 이 PC에 Docker 명령이 없어 컨테이너 빌드·기동 검증은 하지 못했다.

사용자 요청대로 프론트 파일은 변경하지 않았다. 기존 단건·배치 필드는 유지하고 개소·작업 API를 추가했다. 프론트가 새 관리 기능을 보여 주는 작업은 별도다.
