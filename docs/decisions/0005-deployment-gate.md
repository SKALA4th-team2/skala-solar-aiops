# 0005: 배포 게이트

- 상태: 제안
- 날짜: 2026-10-07
- 정한 사람: (아직 없다. 팀이 확정할 때 적는다)

## 배경

배포 게이트는 새로 학습한 모델을 운영 버전으로 올릴지 정하는 합격선이다.

HAIC 스켈레톤의 게이트는 `serving_app/train_and_register.py` 의 `RMSE_GATE = 4.00` 이다. 시험 구간의 RMSE 가 4.00 이하이면 MLflow 에 등록하고 Production 으로 올린다. 넘으면 등록하지 않고 "기존 Production 유지"라고 찍는다. 처음부터 학습할 때(`train_and_register`)와 이어서 학습할 때(`fine_tune`)가 같은 함수(`_register_if_gate_passed`)와 같은 값을 쓴다.

4.00 은 주가의 달러 눈금이다. 하루 발전량은 kWh 눈금이고 시험 구간의 하루 평균이 194kWh 다. 4.00 은 그 2% 다. 이 값을 그대로 두면 통과할 모델을 기대할 수 없다. 직접 돌려 보니 예보 업로드 파일로 학습한 모델이 `[GATE FAILED] rmse=41.59 > 4.0` 으로 막혔다.

정할 것은 세 가지다.

1. 처음 학습한 모델의 합격선
2. 재학습한 모델의 합격선
3. 합격하지 못한 모델을 어떻게 하는가

## 검토한 선택지

처음 학습한 모델

| 선택지 | 얻는 것 | 잃는 것 |
| --- | --- | --- |
| (가) 상대 기준. 같은 시험 날짜에서 7일 평균과 규칙C 를 함께 계산해 "7일 평균 RMSE 의 80% 이하이면서 규칙C RMSE 의 105% 이하"를 본다 | 계절과 평가 기간이 바뀌어도 뜻이 유지된다. 학습이 필요 없는 규칙보다 뚜렷하게 나쁜 모델을 거른다 | 게이트 코드가 기준 예측을 계산해야 한다. 80% 와 105% 는 같은 자료를 보고 고른 값이다 |
| (나) kWh 절댓값(예: 47.5kWh 이하) | 상수 하나만 바꾸면 된다 | 봄이 들어간 기간은 기준 예측의 오차부터 커진다. 업로드 파일이나 분할이 바뀌면 같은 값의 뜻이 달라진다 |
| (다) 제도의 오차율 4%, 6% | 고객이 아는 숫자다 | 하루 합계 모델로는 계산할 수 없다([0003](0003-capacity-and-error-metrics.md)) |
| (라) 32kWh 이하 | 조사에 근거 수치가 있다 | 대상일의 실제 관측을 넣은 상한 구조에만 맞는 값이다. 예보를 넣는 모델에는 쓸 수 없다 |

재학습한 모델

실습 코드를 빈칸의 지시대로 완성하면 재학습은 최근 41행을 쓴다. 표본이 21개 나오고 앞 16개로 학습해 뒤 5개로 게이트를 잰다.

| 선택지 | 얻는 것 | 잃는 것 |
| --- | --- | --- |
| (가) 처음 학습할 때 계산한 합격선(kWh)을 저장해 두고 재학습에도 그 값을 쓴다 | 구현이 단순하다. 조사에 비슷한 값(45kWh)의 통과율이 있다 | 5건의 RMSE 는 크게 흔들린다. 통과가 품질을 보증하지 않는다 |
| (나) 같은 5건에서 현재 모델보다 나쁘지 않을 것 | 상대 기준이다 | 조사에서 통과율이 주입 없음 51.9%, 14% 하락 주입 55.8% 로 거의 같았다. 가르지 못한다 |
| (다) 재학습에 쓰지 않은 180일 이상으로 다시 평가한다 | 표본이 충분하다 | 수준이 바뀐 직후에는 바뀐 뒤의 자료가 180일이 안 된다. 바뀌기 전 자료로 평가하면 바뀐 수준에 맞춘 모델이 불리하다 |

합격하지 못한 모델

| 선택지 | 얻는 것 | 잃는 것 |
| --- | --- | --- |
| (가) 등록하지 않는다. 운영 버전은 그대로 둔다 | 현재 코드의 동작이다. 나쁜 모델이 서비스에 닿지 않는다 | 실패한 모델은 MLflow 의 실행 기록에만 남는다 |
| (나) 등록은 하되 Production 으로 올리지 않는다 | 실패한 모델도 버전으로 남아 비교하기 쉽다 | 코드를 고쳐야 한다 |

## 결정

다음을 제안한다.

**처음 학습한 모델은 (가) 상대 기준으로 본다.** 세 조건을 모두 채워야 올린다.

1. 시험 구간의 RMSE 가 같은 날짜의 7일 평균 RMSE 의 80% 이하
2. 시험 구간의 RMSE 가 같은 날짜의 규칙C RMSE 의 105% 이하
3. 시험 구간의 치우침이 ±10% 이내. ±5% 를 넘으면 올리되 경고를 남긴다

- 시험 구간은 시간순으로 나눈 뒤 20% 다(실습 코드의 분할 그대로). 180일보다 짧으면 게이트를 판정하지 않고 실패로 둔다.
- 7일 평균은 대상일 직전 7일의 발전량 평균이다. 규칙C 는 (직전 7일의 발전량 합 ÷ 그 7일에 대한 예보의 합) × 대상일의 예보다. 둘 다 학습이 없고 업로드 파일의 창 안의 값만으로 계산된다.
- 지금의 업로드 파일이면 시험 구간은 264일(2025-06-09 ~ 2026-02-27)이고 합격선은 47.5kWh 다.

**재학습한 모델은 (가)로 본다.** 처음 학습할 때 계산한 합격선(kWh)을 저장해 두고 뒤 5건의 RMSE 가 그 값 이하이면 올린다.

- 이 게이트는 **기능 시연용**이라고 적는다. 5건으로는 품질을 보증하지 못한다. 망가진 재학습을 거르는 안전장치다.
- 재학습으로 올라간 버전은 바뀐 뒤의 자료가 180일 쌓이면 처음 학습과 같은 상대 기준으로 다시 평가한다. 발표 범위에서는 설계로만 적는다.
- 통과와 실패가 모두 정상 동작이다. 통과를 보이려고 실행한 뒤에 기준을 바꾸지 않는다.

**합격하지 못한 모델은 (가)로 둔다.** 등록하지 않고 운영 버전을 그대로 둔다. 실패 사실을 `aiops.log` 에 남긴다(지금은 재학습이 게이트에서 막히면 경고와 재학습 시작의 두 줄만 남고 결과의 줄이 남지 않는다. 표준 출력에는 `[GATE FAILED]` 가 찍힌다).

80% 와 105% 가 묻는 것은 다르다. 80% 는 "예보를 전혀 쓰지 못하는 망가진 모델인가"를 거른다. 105% 는 "학습이 필요 없는 규칙보다 뚜렷하게 나쁜 모델인가"를 거른다. 105% 조건은 학습한 모델이 규칙보다 낫다는 것을 입증하는 조건이 아니다. 규칙C 와 비슷한 수준이면 통과시키는 까닭은, 같은 입력이면 모델 종류에 따른 차이가 작다는 조사 결과 때문이다.

이 기준에는 한계가 있다. 80% 와 105% 는 같은 평가 구간에서 정하고 센 값이다. 예보 자료가 2022-07 이후에만 있어 다른 해로 검증하지 못했다. 시험 구간에 3 ~ 5월이 없다. 지금의 통과 결과를 운영 품질의 보증으로 쓰지 않는다.

## 다시 볼 조건

- 봄(3 ~ 5월)이 들어간 시험 구간을 얻을 때. 80%, 105% 가 그 구간에서도 같은 뜻인지 본다
- 업로드 파일의 종류가 바뀔 때([0002](0002-inputs-and-prediction-time.md)). 발전량만 넣는 구조라면 규칙C 를 계산할 수 없어 기준이 달라진다
- 재학습 게이트의 통과율을 시연에 쓸 모델로 직접 잰 뒤
- 치우침의 경고 기준(±5%)에 직접 학습한 모델이 걸리는 일이 되풀이될 때. 학습 방법이나 기준 가운데 무엇을 고칠지 정한다
